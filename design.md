# design.md

The shared visual language behind `kkrll-next`, `good-looking`,
`you-live-like-this` and `dbd`. Code lives in `tokens.css` / `base.css` /
`motion.css`; this file is the *why*, and the part that survives a rewrite.

---

## 1. The ramp rule

Every colour is a base plus three steps. **The numeric suffix is how much of
the base colour remains:**

| Token | Meaning | Typical use |
|---|---|---|
| `--foreground` | 100% | body text, primary ink |
| `--foreground-07` | 70%, closest to base | secondary text, captions |
| `--foreground-05` | 50% | tertiary text, disabled |
| `--foreground-03` | 30%, furthest | hairlines, placeholder |
| `--background` | 100% | page ground |
| `--background-07` | 70%, closest to base | cards, raised surfaces |
| `--background-05` | 50% | borders, dividers |
| `--background-03` | 30%, furthest | strong rules, wells |

Read a suffix as **distance from base, never as lightness.** Under `.dark` the
hexes invert but every relationship above still holds, which is the entire
point of writing it this way: a component authored against `-07` stays correct
in both themes without a single dark-mode override.

> **Known inconsistency.** `good-looking` and `you-live-like-this` invert this
> on the *background* ramp only — there `-05` (`#f5f5f5`) sits closer to base
> than `-07` (`#e5e5e5`). Their foreground ramps are correct. Fix on migration;
> see §6.

### Translucent variants

`--background-semi`, `--background-07-semi`, `--background-05-semi` are the same
steps at 30% alpha, for insets and hairlines that must let the layer beneath
show through. Use these instead of `color-mix()` at call sites so the alpha
stays consistent.

## 2. Palette

The warm **kkrll** palette is the shipped default. Other projects override.

| Token | Light | Dark |
|---|---|---|
| `--background` | `#f1eadf` | `#0a0a0a` |
| `--background-07` | `#c8c1bb` | `#1f1f20` |
| `--background-05` | `#a6a29e` | `#3d3d3f` |
| `--background-03` | `#8a8580` | `#565658` |
| `--foreground` | `#171717` | `#ededed` |
| `--foreground-07` | `#1f1f20` | `#6b6a69` |
| `--foreground-05` | `#323235` | `#4b4a49` |
| `--foreground-03` | `#4a4a4d` | `#3a3938` |

**Overriding.** Redeclare the *plain* var after importing, never the `--color-*`
one — the `@theme inline` mapping already points at the plain var, so touching
`--color-background` breaks the indirection that makes dark mode work.

```css
@import "tailwindcss";
@import "@kkrll/design/theme.css";

:root { --background: #ffffff; --background-07: #e5e5e5; }
.dark { --background: #0a0a0a; }
```

Dark mode is driven by a `.dark` class, not `prefers-color-scheme`, so the
theme can be toggled. `.dark` (rather than `:root.dark`) is used deliberately —
it matches both `<html class="dark">` and a nested `<div class="dark">`, so a
subtree can be inverted without a second palette.

## 3. Type

The library ships **roles, not families** — `--font-sans-stack`,
`--font-mono-stack`, `--font-serif-stack`, mapped to Tailwind's `font-sans` /
`font-mono` / `font-serif`. Each project assigns real families.

| Project | Sans | Serif | Mono |
|---|---|---|---|
| kkrll-next | Geist (next/font) | Recia (Fontshare) | Geist Mono (next/font) |
| good-looking | Supreme | Sentient | JetBrains Mono |
| you-live-like-this | Supreme | Sentient | JetBrains Mono |
| dbd | Geist (local) | Sentient | JetBrains Mono |

> **next/font trap.** In `kkrll-next`, `--font-geist-sans` is generated by
> `next/font` with a hashed family name and injected via the class on `<body>`.
> Never redeclare it in CSS — a hardcoded `"Geist"` silently shadows the real
> hashed name and you get the fallback with no error anywhere.

### Conventions (guidance, not shipped CSS)

Headings differ enough between projects that `base.css` deliberately does not
set their size or case. The house style, where you want it:

- **Uppercase + mono** for small labels, `h2`/`h3`, and anything secondary.
  This is the signature move across all four projects.
- **Sentence case** for `h1` and body.
- Secondary text = mono + `--foreground-07` + uppercase + `0.875rem`.

## 4. Motion

| | Value |
|---|---|
| Travel distance | **24px**, always |
| Enter | `0.2s ease-out` |
| Exit | `0.15s ease-in` |
| Press / micro | `0.08s ease-in-out` |
| Colour | `0.2s ease-in-out` |

Exits are faster than entrances — leaving should feel like it gets out of the
way, arriving should feel placed. Keyframes are camelCase (`fadeInFromBottom`),
matching kkrll-next.

View-transition wiring is **not** shipped: transition names are app-specific.
Map the keyframes onto your own names in the app, and always guard with
`@media (prefers-reduced-motion: no-preference)`.

---

## 5. Shape & spacing

- **Corners:** `corner-shape: superellipse(1.333)` globally. Continuous
  curvature; degrades to plain `border-radius` where unsupported.
- **Spacing:** 8px base. `8 / 16 / 24 / 32` covers nearly everything; 24px is
  the default gutter and matches the motion travel distance.
- **Radii:** `8px` for controls, `100rem` for pills.

### Fixed on the way in

`kkrll-next` used `--background-07-semi` and `--background-semi` without ever
defining them, so `.nice-button`'s light-mode border (`1px solid
var(--background-07-semi)`) resolved to an invalid value and the whole
declaration was dropped — the button rendered borderless. Both are now defined
in `tokens.css`.

## 7. What this library is not

No components. The only component duplicated across all four projects is
`Divider.tsx`, and one component does not justify a package, a build step and
four dependency bumps. Tokens are the thing that actually drifts; components
are the thing that actually differs. If a second and third component genuinely
converge, revisit — not before.
